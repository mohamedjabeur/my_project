# ENIMIA Autonomous Vehicle (ros2 workspace)

> Full project documentation (French): `DOCUMENTATION.md`. Dated log: `PROGRESS.md`.

## What it does
ROS 2 workspace for the ENIMIA Black Edition autonomous outdoor RC car (Ackermann, rear-wheel BLDC drive,
front steering, 1.704 m wheelbase, steer limit ±0.21 rad → min turning radius ≈ 8 m, forward-only).
Target: Shell Eco-marathon-style ~1 km closed circuit (7 m road, 2 lanes, stop signs every 150 m).
Covers simulation (Gazebo) and the real car: teleop, Nav2, lidar + camera perception,
drive chain to an ESP32. Sim and real share the same stack above the ESP32 layer.

## Tech stack
- ROS 2 Humble, Ubuntu 22.04, colcon, Python (ament_python) + CMake packages; no git repo yet
- Simulation: Ignition Gazebo (`ign gazebo`, `ros_gz_bridge`, `ros_gz_sim`) — not Gazebo classic
- Nav2 (Smac Hybrid-A*/Dubin planner, Regulated Pure Pursuit, custom BTs without spin/backup),
  no map / SLAM (removed 2026-11-08)
- Perception: numpy/OpenCV only (classical vision, no AI/YOLO)
- Hardware: Livox Mid-360 lidar, BNO055 IMU, OAK-D Lite camera (RPLIDAR A1M8 / V4L2 still supported), ESP32 (Arduino, BLDC + steering servo, serial 115200)

## Architecture notes / gotchas
- Frames: `odom` → `base_footprint` (middle of wheelbase, on the road); rear axle is 0.852 m behind it.
  Sensors: lidar 0.78 m high tilted 4° down; camera 0.732 m, 10° down, 800×450, HFOV 100°.
- Two sim drive paths exist: `localization/{cmd_vel_to_drive, odom_tf}` (direct, ground-truth odom; used by
  `localization/teleop.launch.py` and therefore by `navigation/bringup`) vs `vehicle/sim.launch.py`
  (virtual ESP32 + encoder odometry, mirrors the real car). Don't run both at once.
- `vehicle.yaml` is shared by sim and real. `ticks_per_rev: 90` is a placeholder — MEASURE on the real car.
- Firmware has `SIMULATE_MOTOR 1` by default (no motor needed); set 0 when motor + halls are wired.
- Serial protocol (see `vehicle/ackermann.py`): PC→ESP32 `C <speed> <steer>` @50 Hz, `E` e-stop; ESP32→PC `S <ms> <ticks> <steer>`; 500 ms watchdog.
- Real car must run `ackermann_controller` with `cmd_timeout: 0.5`; keep 0 for keyboard teleop.
- Track has NO centre line any more (removed 2026-11-04): `estimate_lane` falls back to the nearest edge line + nominal 3.5 m lane width, so the ego lane = the lane next to the nearest edge.
- rclpy trap: with `use_sim_time` the Gazebo `/clock` runs at 400-900 Hz and starves a SINGLE-threaded executor (node alive, 70 % CPU, publishes nothing). `line_detector` / `lidar_obstacle_detector` therefore spin a `MultiThreadedExecutor`. perception Python sources are copied to `build/` → re-run `colcon build --packages-select perception` after editing them (yaml/launch files are symlinked).
- Before relaunching in the sim, kill EVERYTHING (stale nodes from older launches caused a 3.0 m/s clamp via an old `cmd_vel_to_drive` and doubled TF). In scripts never `pkill -f` a pattern that also appears in your own command line (it kills the caller, exit 144). Closing the `ign gazebo gui` window also stops the server.
- Braking (measured in sim): rear-wheel-only stops from 5.5 m/s in ~5 m (3-3.5 m/s²); `autonomy decel` 3.0. A 3 m stop needs front brakes (not modelled).
- Gazebo here runs software-rendered (real-time factor ~0.1, camera < 1 Hz wall): wait ≥ 6-9 s after teleporting before reading perception results.
- Sim test 2026-11-08 (goal 160 m ahead, 68 obstacles every ~12 m alternating lanes): 0 collisions, 0 line crossings, 10 obstacles passed, stops only at the goal (`eval_lap.py`). `line_detector` once started frozen (no `lane_valid`, car blind): check `ros2 topic hz /perception/camera/lane_valid` after launch, restart it if 0. A `pkill -f` whose pattern appears in the tool command line kills the caller (exit 144): put kill commands in a script file.
- Debugging sim freezes: `line_detector` once sat at 100 % CPU publishing nothing because `publish_debug` set `Image.data = bytes` (ROS validates it byte by byte in Python, seconds per frame): use a numpy uint8 array (fixed). Stale nodes of earlier launches (e.g. a forgotten `cloud_to_scan.py`) duplicate `/scan` and eat CPU: `ps aux | grep python3` before testing. An empty yaml list (`car_mask: []`) arrives as None (fixed in line_detector).
- "Detected jump back in time" = a stale node of an old launch or a node without `use_sim_time` (robot_state_publisher too: `description.launch.py use_sim_time:=true` in sim). Before relaunching kill ALSO `world_markers speed_display joint_state_publisher camera_fov_marker rviz2 slam cloud_to_scan.py`; `ros2 topic info /clock -v` must show 1 publisher and `ros2 node list | sort | uniq -d` nothing.
- `lap.launch.py` (so `drive.launch.py`) REFUSES to start if an `ign gazebo server` already runs (message with its PID; override `ENIMIA_ALLOW_SECOND_SIM=1`): two sims = 2 `/clock` publishers = RViz/tf2 'jump back in time' flood. Never leave a background launch running while the user starts theirs.
- Stale/unused: `world/terrain.launch.py`, `world/terrain(2).urdf`, `world/generate_urdf(2).py` (Gazebo classic,
  package `shell_eco_terrain` doesn't exist here); `.pytest_cache` dirs inside src.
